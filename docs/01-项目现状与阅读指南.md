# 项目现状与阅读指南

> 最后核对：2026-09-26。本文以当前分支 `feature/v1.5-acceptance` 的代码为准。

## 1. 一句话定位

Veritas RAG 当前是一个面向个人知识库的、具备三层记忆和受控 ReAct 运行时的问答系统。知识库检索与联网搜索已经统一包装为工具，所有在线 RAG 请求都由新 ReAct Graph 执行。旧固定 Graph 已退出 API 运行路径，仅有少量历史评测脚本尚待迁移。

## 3. 当前必须牢记的边界

1. `AGENT_RUNTIME_MODE` 默认是 `react`；旧值和非法值会被在线 Runtime 归一化为 `react`。
2. 当前 Trace 能定位一次运行和一次工具调用，但不是完整事件溯源系统，不能从失败节点继续。
3. 旧 `backend/graph/` 不再被在线 Runtime 导入，但历史评测脚本迁移完成前暂不删除。
4. 目标 MySQL 必须执行 `20260926_react_runtime.sql` 和 `20260926_react_default.sql`。
6. 当前认证仍包含开发期默认用户路径，生产前必须替换为真实认证和授权边界。
7. 文档上传边界是 Markdown-only；其他格式属于后续产品需求，不应写成已支持。
8. 模型配置统一使用 `deepseek-v4-flash`，不要把旧的 Pro/Flash 角色差异写回文档。

## 4. 推荐阅读顺序

```text
README.md
  └─ docs/README.md
       ├─ 01 项目现状与阅读指南
       ├─ 02 系统架构与运行流程
       ├─ 03 状态、追踪与失败恢复
       ├─ 04 工具系统与检索
       ├─ 05 上下文工程与记忆机制
       └─ 06 数据库迁移与 ReAct 上线验收
```

按源码阅读时建议遵循一次请求的真实调用链：

1. `backend/api/v1/endpoints/rag.py`：请求入口、SSE、Trace 收口和消息持久化。
2. `backend/agent/runtime.py`：唯一在线 ReAct 入口、Deadline 与运行预算。
3. `backend/agent/state.py`、`schemas.py`：状态与稳定数据契约。
4. `backend/agent/graph.py`：`decide → act → observe → decide` 循环。
5. `backend/agent/controller.py`：动态上下文和结构化决策。
6. `backend/agent/tools/`：工具注册、权限、幂等和适配器。
7. `backend/agent/evidence/ledger.py`：证据编号、覆盖和冲突。
8. `backend/agent/context/builder.py`：动态 Prompt 组装。
9. `backend/agent/memory/service.py` 与 `backend/services/memory/memory_service.py`：三层记忆。
10. `backend/services/trace_service.py`：当前持久化观测能力。

只有迁移历史评测脚本时才需要阅读 `backend/graph/`，不要把它作为当前架构入口。

## 5. 文档真相优先级

出现冲突时按以下顺序判断：

1. 当前代码与数据库迁移脚本；
2. 自动化测试；
3. 本目录 01～06 的核心文档；
4. 产品需求与评测记录；
5. `规划与参考/` 中的未来蓝图。

规划文档描述的是目标能力，不等于当前已经实现。
