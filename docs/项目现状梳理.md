## 1. 项目定位

Veritas RAG 是面向私有知识库的 Agentic RAG 问答系统。后端使用 FastAPI 提供 API，LangGraph 编排查询流程，MySQL 保存业务数据和正文，Chroma 保存 Child Chunk 的 Dense 向量，前端使用 React + Vite。

当前主链路：

```text
上传文件 -> 解析 -> Parent-Child 分块 -> Dense/BM25 入库
用户问题 -> 记忆加载 -> Query Rewrite/Decomposition -> 路由
         -> Dense + BM25 -> Weighted RRF -> 多样性控制
         -> Parent 回补 -> BGE Reranker -> Evidence Grading
         -> Reflection/Web Search（按需）-> 生成 -> 引用/Verification
         -> 会话摘要与长期记忆更新
```

## 3. 运行方式

后端统一使用 Conda 环境 `cook-rag-1`（当前 Python 3.12.7）。V1.5 的所有 LLM 工作负载统一使用 `deepseek-v4-flash` 以控制成本：

```bash
conda activate cook-rag-1
python -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

配置入口是仓库根目录 `.env`，模板为 `backend/.env.example`；默认数据目录为 `data/chroma` 和 `data/uploads`。前端：

```bash
cd frontend
npm install
npm run dev
```

## 5. 已知边界

- V1 API 仅接受 Markdown（`.md`）；代码中保留的 PDF/DOCX/PPTX/HTML/TXT/图片解析器暂不对外开放。
- 文档内嵌图片的完整图文联合检索、图片向量和视觉证据回传仍未完成。
- Sparse 主链路是独立 BM25，不是 BGE-M3 learned sparse。
- HTML 当前以基础文本化为主；PDF 表格和跨页结构仍可能丢失布局信息。
- DuckDuckGo provider 是占位实现，联网搜索应优先使用 Tavily/SerpApi。
- `backend/README.md` 和本文件描述当前实现；历史评估记录只用于追溯，不代表全部仍在线上生效。
