# V1.5「更懂用户」个人助手 PRD

上级导航：[`docs/README.md`](README.md) · 关联目标架构：[成熟 Agentic RAG 工程落地设计方案](<成熟 Agentic RAG 工程落地设计方案.md>)

> 需求基线：2026-09-06。本文档是后续前后端实现与验收的唯一范围约束。

## 1. 目标

将 V1 的 Markdown 知识库问答升级为可控的个人助手：能记住用户明确确认的偏好、约束和项目状态，支持长对话与会话/项目隔离，并让每轮回答可追踪、可解释、可纠错。所有 LLM 调用统一使用 `deepseek-v4-flash`，优先控制成本。

## 2. 范围与非目标

V1 入库 API 只接受 Markdown（`.md`）。PDF、DOCX、PPTX、HTML、TXT、图片解析器可保留在代码中，但本版本不对外开放。V1.5 不做 MCP、Skill、多 Agent、自动修改代码/Prompt 的“自我进化”以及完整图文联合检索。

## 3. 核心场景

1. 用户在项目会话中询问 Markdown 知识库，答案带可核查引用。
2. 连续多轮讨论任务，助手保留目标、决定、否定项和未决问题。
3. 用户表达偏好或项目约束，助手提出记忆卡片供确认，而非静默写入。
4. 切换项目或会话后，不泄露其他项目的记忆和消息。
5. 用户可查看、编辑、确认、失效、删除记忆及其来源。
6. 用户可查看本轮检索、引用、记忆使用、耗时和反思过程。
7. 在会话分支中试验方案，不影响主会话。

## 4. 信息架构与隔离

```text
User -> Workspace -> Knowledge Bases -> Sessions -> Messages / Summary / Branches / Traces
                                 \-> Memories: Profile / Preference / Constraint / Project State
```

每个请求绑定 `user_id`、`kb_id`、`session_id`、`branch_id`、`request_id`，重试额外绑定 `parent_request_id`。session 消息只在本 session 可见；project memory 只能在所属 kb 使用；user memory 需经过相关性筛选；branch 的消息和摘要独立。

## 5. 记忆治理

记忆类型：`profile`、`preference`、`constraint`、`project_state`。每条记忆包含 `memory_id/type/key/value/scope/source/confidence/status/created_at/updated_at/last_confirmed_at/expires_at`。

来源：`explicit_user`、`user_confirmed`、`inferred`、`imported`、`system`。只有明确表达或用户确认的记忆可作为高置信度事实；inferred 记忆必须先进入待确认状态。普通知识库事实不得自动沉淀为长期记忆。支持 create、merge、replace、invalidate、none；服务端强制校验归属、作用域、候选 ID、幂等和事务。

前端必须显示新记忆确认卡片、来源、置信度、最近使用时间和审计记录；用户拒绝或删除的记忆不得自动重建。

## 6. 上下文策略

```text
当前问题 -> 证据 -> working memory -> session summary -> 最近 3 轮
         -> 选择后的长期记忆 -> 用户画像
```

使用真实 tokenizer 计算分区预算；超预算按优先级裁剪，不破坏 JSON 和引用标记。working memory 仅存在于当前请求；摘要更新必须同时读取上一版摘要和未摘要消息；所有历史、文档和记忆区块都标记为数据而非指令。

## 7. 可观测性

每轮生成 Trace，包含 `memory.load`、`query.rewrite`、`query.decompose`、`route.plan`、`retrieval.dense`、`retrieval.sparse`、`rrf`、`rerank`、`evidence.grade`、`reflection`、`generation`、`verification`、`memory.update` Span（按实际执行记录）。记录耗时、状态、错误、模型、token、候选数、Top-K、evidence/memory IDs、反思轮次和停止原因；敏感正文默认脱敏，仅保留摘要。会话详情提供可折叠的运行详情抽屉。

## 8. 后端需求

完善 `backend/api/v1/endpoints/memory.py` 的分页筛选、确认/编辑/失效/删除和审计；新增 `GET /users/sessions/{id}/trace`、`POST /rag/feedback`、`GET /knowledge/{kb_id}/capabilities`；非 Markdown 上传返回错误码 `unsupported_file_type`。增加 trace/span 与 feedback 持久化，记忆 source/confidence/expiry 字段，文档 content hash/version/incremental status；所有 LLM tier 映射 Flash。

## 9. 前端需求

Chat 展示回答模式、引用、使用的记忆和运行详情；Memory 页面支持筛选、确认、编辑、删除、审计；Session 页面支持归档、重命名和分支；Knowledge 页面明确 Markdown-only、解析进度、版本和失败原因；Settings/Observability 展示成本策略、Trace 和数据导出。记忆与证据必须视觉分区，运行详情默认折叠，错误提示包含下一步动作，并支持键盘、窄屏和 reduced motion。

## 10. 验收指标

- 非 Markdown 上传 100% 返回 `unsupported_file_type`。
- session、branch、project memory 隔离测试零交叉。
- 用户删除/拒绝记忆不会重新注入。
- 每轮可通过 request_id 找到完整 Trace。
- 引用 ID 存在且属于允许证据集合。
- 记忆选择准确率 ≥90%，错误长期记忆写入率 ≤2%，摘要关键事实保留率 ≥95%。
- Citation precision ≥95%，拒答 precision ≥90%。
- 单轮仅使用 Flash，反思最多 3 轮；持续记录 P50/P95 延迟和 token 成本。

## 11. 实施顺序

P0：Flash-only、Markdown-only、错误码、数据字段与 feature flag。  
P1：记忆治理 API、确认/拒绝、审计和前端 Memory。  
P2：session/branch 隔离回归、真实 tokenizer、摘要漂移检测。  
P3：Trace/Span 持久化、SSE 关联、运行详情 UI。  
P4：反馈闭环、评测集、CI 门禁和体验收尾。

## 12. 后续版本

V2 在本 Trace、权限、超时和审计基础上增加 Tool Registry；V3 增加 MCP/Skill Adapter；只有单 Agent + 工具层出现明确瓶颈后才引入 Supervisor/多 Agent。
