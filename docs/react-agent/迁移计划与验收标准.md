# ReAct 重构迁移计划与验收标准

上级导航：[V1.6 ReAct Agentic RAG 架构重构需求](README.md)

## 1. 迁移原则

1. 先抽象 Tool 和状态协议，再替换 Graph；不先删除可工作的检索代码。
2. 新旧 Runtime 并存，通过 feature flag 和 shadow traffic 对比。
3. 记忆、消息、引用和 Trace 数据保持向后兼容；必要字段通过迁移新增。
4. 每个阶段都能独立测试和回滚，避免一次性重写整个后端。
5. 所有 Agent 决策有步数、时间、token、费用和权限上限。

## 2. 阶段一：契约与基础设施

交付：

- `AgentState/AgentDecision/ToolCall/Observation/EvidenceLedger` Pydantic schema。
- Tool Registry、Tool Gateway、Policy Guard 和统一错误码。
- `knowledge_search`、`web_search` 只读 Adapter，底层复用现有服务。
- `agent_tool_calls`、`agent_observations` 或等价可审计存储。
- Trace 新事件和 span 字段。

验收：

- Tool 参数越权时被服务端覆盖或拒绝。
- timeout/retry/idempotency 单测通过。
- 相同 tool_call_id 不重复执行。
- Tool 输出统一生成 Evidence 和 Observation。

## 3. 阶段二：ReAct Runtime

交付：

- `initialize -> decide -> act -> observe -> decide -> verify -> commit` LangGraph。
- Native tool calling 适配和结构化 Decision fallback。
- max iterations、调用次数、token、时间和无进展停止条件。
- `AGENT_RUNTIME_MODE=react_shadow`。

验收场景：

1. 普通知识库问题调用一次 KB 后回答。
2. 第一次检索缺失时改写 query 再调 KB，第二次补足后回答。
3. KB 不含最新信息且允许联网时转 Web。
4. KB 和 Web 都不足时明确拒答，不超过调用上限。
5. 用户未允许联网时不会调用 Web。
6. 重复工具调用被无进展检测阻止。

## 4. 阶段三：上下文工程

交付：

- ReAct Context Builder 和 `chat/rag_standard/rag_deep/long_context` profiles。
- Working Memory v2、Evidence Ledger、Observation Compactor。
- 完整 Tool 输出外置，Prompt 只加载摘要和 Evidence。
- 每轮 section token、裁剪、selected evidence/memory IDs 进入 Trace。

验收：

- 每轮 Prompt 都能解释各 section 的来源、预算和裁剪原因。
- 多次工具循环不会线性重复注入旧结果。
- 必选区块不会被静默丢弃。
- 300k-capable 模型仍按 profile 控制普通请求成本。

## 5. 阶段四：三层记忆重写

交付：

- Working Memory v2 只存在于 Run State。
- Session Summary v2 和 branch-aware 最近消息加载。
- 长期记忆混合召回、时效、stale、supersede、tombstone 和冲突组。
- Hot path 明确记忆与 background extraction 的分离。
- 用户确认/拒绝/编辑/删除继续可用。

验收：

- 工作记忆不跨请求泄漏。
- 新会话可读取同一用户已确认的 user memory。
- 不同用户、项目、分支不串数据。
- 过期/冲突/删除记忆不会进入默认 Prompt。
- 用户纠正后新事实优先，旧事实仍可审计。
- 知识库或网页事实不会被自动写入用户画像。

## 6. 阶段五：验证、评测和切流

### 6.1 离线数据集

至少覆盖：

- 单次 KB 检索即可回答；
- 查询改写后才能召回；
- KB -> Web 切换；
- 多来源冲突；
- 负样本拒答；
- 指代和多轮上下文；
- 跨会话用户偏好；
- 过期/冲突长期记忆；
- Prompt Injection 文档；
- 循环和预算极限。

### 6.2 指标

| 能力 | 指标 |
|---|---|
| 工具决策 | tool selection accuracy、unnecessary call rate |
| 循环 | avg iterations、no-progress rate、budget exhaustion rate |
| 检索 | Recall@K、MRR、NDCG、Unique Parent Ratio |
| 证据 | slot coverage、citation precision/recall、faithfulness |
| 拒答 | refusal precision/recall、false answer rate |
| 记忆加载 | memory precision/recall、stale/conflict injection rate |
| 记忆更新 | create/merge/replace accuracy、duplicate rate |
| 上下文 | input tokens、truncation rate、compaction fidelity |
| 性能 | p50/p95 latency、tool latency、cost per successful answer |

### 6.3 切流门槛

新 Runtime 至少达到：

- 旧基线 Recall/Citation/Faithfulness 不下降；
- 负样本错误作答率不高于旧版；
- 无权限工具调用为 0；
- 无限循环为 0；
- 请求幂等失败为 0；
- 记忆跨用户/跨项目泄漏为 0；
- p95 延迟和平均成本在约定预算内。

先内部 shadow，对比通过后灰度 5% → 25% → 50% → 100%。每一档需要至少一个完整评测周期，无严重权限、数据一致性或引用事故。

## 7. 数据库迁移建议

现有表保留。建议新增或扩展：

```text
rag_runs
  runtime_mode, iteration_count, stop_reason,
  tool_call_count, budget_profile, input/output/cost totals

agent_tool_calls
  tool_call_id, run_id, tool_name, args_hash, args_summary,
  status, retry_count, started_at, ended_at, latency_ms, error_code

agent_observations
  observation_id, tool_call_id, status, summary,
  evidence_ids, supported_slots, missing_slots, conflicts, output_ref

long_term_memories
  conflict_group, embedding_ref, stale_at,
  confirmation_count, deletion_tombstone
```

迁移脚本必须可以重复检查并安全执行；生产数据库不能依赖 `create_all`。

## 8. 代码迁移映射

| 当前代码 | 目标位置 | 处理方式 |
|---|---|---|
| `backend/graph/graph.py` | `backend/agent/graph.py` | 新建 ReAct 图，旧图保留回退 |
| `query_nodes.py` | `agent/controller.py` + working memory | 收敛 rewrite/route 到每轮 Decision |
| `retrieval_nodes.py` | `tools/knowledge_search.py` | 复用底层检索和 Evidence Packer |
| `web_nodes.py` | `tools/web_search.py` | 改成 Tool Adapter |
| `reflection_nodes.py` | Agent 下一轮 Decision | 删除独立 Reflection 路由概念 |
| `generation_nodes.py` | Controller + Verifier | 最终回答和发布验证分开 |
| `context_assembler.py` | `agent/context/builder.py` | 增加 ReAct section/profile/compaction |
| `memory_service.py` | loader/updater/conflict | 按加载、更新、冲突职责拆分 |
| `trace_service.py` | Run/Tool/Observation Trace | 增加工具和迭代可观测性 |

## 9. 测试分层

```text
Unit
  schema / registry / policy / budget / fingerprint
  memory conflict / TTL / context compaction / ledger

Contract
  knowledge_search / web_search input-output
  model decision schema / native tool calls

Graph
  each conditional path / stop condition / retry

Integration
  MySQL + Chroma + model stub + streaming API

Evaluation
  retrieval / generation / memory / multiturn / adversarial
```

模型测试必须使用可重复 stub 覆盖工具调用序列；端到端真实模型评测用于质量门槛，不能替代确定性单测。

## 10. 完成定义

只有同时满足以下条件，才可宣称完成 ReAct 重构：

- KB 与 Web 均通过统一 Tool Gateway 调用；
- Agent 能基于 Observation 在至少两轮 Action 之间做不同决策；
- 每轮具备结构化 Decision、Action、Observation 和停止原因；
- Evidence Ledger 决定引用，Memory 不作为证据；
- 三层记忆按生命周期加载和更新，长期记忆具备冲突/时效治理；
- 动态 Prompt 具备分区、预算、压缩、来源和 Trace；
- 新旧 Runtime 可灰度、回退且不会重复写消息/记忆；
- 测试、离线评测、前端事件展示和运维文档全部同步更新。
